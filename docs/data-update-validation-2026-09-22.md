# 每日快照更新与引用修复：实施及验证

## 当前行为

- 桌面应用启动时补查，之后每小时检查是否达到 24 小时更新周期；应用关闭后不运行。
- 统一协调器依次核验国服公告、同步 DataTFT、刷新攻略。失败保留历史并退避重试；同一更新任务不并发执行。
- 服务器版本与来源快照分别记录。只有国服官方公告中的明确补丁及可核验生效信息才能确认跨版本升级；编号不明的热修复、预告、外服攻略均不能触发升级。
- 服务器状态尚未确认时，只能刷新已有来源版本，不能激活其他补丁。回答和界面均说明版本状态待核验。确认服务器升级后，旧补丁退出当前推荐检索，即使新快照暂缺。
- 同版本的新内容保存为新快照；相同内容复用原快照，更新任务记录检查时间。候选目录、关联解析及 active 指针在同一个 SQLite 事务中发布，失败一起回滚。
- 同一进程内问答与发布互斥，避免回答中途换快照。旧证据与原始响应保留，不改版本标签。

## 已修复的问题

DataTFT 新前端把版本常量改为带生效时间的版本列表，基础目录另在依赖模块中。适配器现可识别该结构并继续发现目录模块，不执行远端 JavaScript。

真实同步还发现替补英雄编码后不再固定附带价格字符。旧解码器错误吞掉下一棋子的站位字符，导致位置重复。现保留下一站位，并校验详情 ID、标题、棋子身份和位置；不合格的抓取不能发布。

引用不再按网站总览 URL 合并。模型的每条攻略建议携带引用编号，后端检查当前请求、阵容、版本与快照；编号在模型上下文中不包含内部英雄编码。没有可靠详情 URL 的 DataTFT 证据在应用内展示保存的正文、阵容 ID、快照、版本和抓取时间，总览链接明确标注为总览。

有来源评级的筛选先按来源评级选候选，再应用数量限制，避免按阵容名字截取导致强势问答只看到部分低评级阵容。来源评级仍是作者观点；没有样本量及统计窗口的数值不能作为统计排名依据。
